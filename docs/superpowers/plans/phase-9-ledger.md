# Phase 9 ledger (reader)

Plan: `2026-10-23-phase-9-reader.md` on `claude/phase-plans-7d02cb` (PR #3, docs only). Master plan: Part E Phase 9, Part F, A6, A9, A16, C3, C6, Q11, R1. The spec the plan cites is not in this environment; the plan and the master plan are the source. Branch `phase-9-reader`, cut from main at cad20d4.

## Conflict scan (against main at cad20d4)

- **`content_sources` exists** (`2026_10_23_100002`, designed in Phase 2, unused): `media_id` (cascade), `access_type` enum(public_domain, licensed, user_owned, external_link), `format` enum(epub, pdf, cbz, cbr, images, url), `storage_path`, `url`, `license` (not null), `rights_holder`, `owner_user_id` (null on delete), `verified_by` (FK users, null on delete), `verified_at`. No model, factory, policy or enum classes. It has no file state, size, checksum or idempotency key, so a source cannot say "file not fetched yet", "conversion failed" or "already imported".
- **`reading_progress`** already has `content_source_id` (null on delete) and `locator jsonb` (Phase 5). **`LogProgress::handle(User, Media, float $percent, ?int $page, ?string $chapter, ?array $locator, int $seconds)`** has no `content_source_id` parameter, appends a `reading_history` row and records a `reading_progress` interaction on every call. A reader that saves every 2 seconds would flood both.
- **Admin-only accounts** (#32): the `reader` middleware keeps admins off every reader route, and an admin's Livewire requests to reader components are refused. So admins cannot use reader routes, and readers are never admins. Admin pages are `Route::livewire` under `can:access-admin`, with navigation in `config('bookflix.admin_navigation')`.
- **Visibility:** `Media::visibleTo` and `Media::isGatedFor` hold the mature gate; ProhibitedContent rows are soft-deleted (#22) and filtered at ingestion by `RecordValidator`.
- **Ingestion:** providers implement `MetadataProvider` (`key`, `page`, `find`, `normalize`), are registered in `config('bookflix.providers')` with `allowed_hosts`, and run through `SyncProvider` → `FetchProviderPage` → `IngestionPipeline::import()`, which returns an `ImportOutcome`, not the media. `external_sources` rows come from `ExternalSourceSeeder` (first-or-create) and data migrations.
- **Feeds today:** Standard Ebooks' full OPDS feeds (`/feeds/opds/all`, `/feeds/opds/new-releases`) answer 401 (Patrons Circle members only); the Atom new-releases feed (the 15 newest) is public. Project Gutenberg answered 503 to this environment's proxy; tests fake HTTP anyway.
- **Media types:** `novel` and `nonfiction` are `reflowable`; `manga`, `comic-book`, `graphic-novel` and `picture-book` are `paged`; `manhwa`, `manhua` and `webcomic` are `vertical_scroll`.
- **Security headers:** `SetSecurityHeaders` is global (`nosniff`, `Referrer-Policy: same-origin`, `X-Frame-Options: DENY`, Permissions-Policy). There is no CSP.
- **Scripts under a nonce:** Livewire 4 (`FrontendAssets::nonce`) and Flux (`FluxManager::nonce`) both read `Vite::cspNonce()`, so `Vite::useCspNonce()` nonces `@livewireScripts`, `@fluxScripts`, `@fluxAppearance` and `@vite`. One inline script needs a nonce attribute by hand (`partials/head.blade.php`); `filter-islands` uses `type="application/json"`, which CSP does not execute. No inline `on*=` handlers. Fonts are self-hosted at build time (`laravel-vite-plugin/fonts`).
- **Alpine evaluates expressions with `new Function`.** Livewire 4's docs (search-docs, livewire/livewire 4.x `csp`): without `csp_safe`, Livewire and Alpine need `'unsafe-eval'`; `csp_safe` switches to the Alpine CSP build, which restricts expressions. The app has about 130 `x-data`/`x-on`/`x-init`/`x-bind` attributes, many with arrow functions and assignments.
- **Uploads:** there is no `config/livewire.php`; Livewire temporary uploads default to the `local` disk (`storage/app/private`), with Livewire's default rule `file|max:12288` (12 MB). The only upload today is the avatar.
- **Purge:** `bookflix:purge-deactivated-accounts` deletes the avatar and exports, then the user. `content_sources.owner_user_id` is null on delete, so an uploaded file and its row would outlive the account.
- **Story page:** shows provider attributions with links back; there is no "Read" button and no "Where to read" list.
- **Tooling here:** PHP 8.4 with `zip` and `fileinfo`; Postgres 16 with `vector`, `pg_trgm` and `unaccent`; Redis installed but stopped (tests use the array cache and the sync queue); no `unar`, `unrar`, `7z` or `bsdtar`.
- **Libraries:** `foliate-js` 1.0.1 is on npm (MIT); `pdfjs-dist` 6.5.438 (Apache-2.0).

The existing columns stay. | One more migration on a table that has no rows anywhere yet. |
| P9-R3 | `ContentAccessGate::allows(User, ContentSource)` is true only when: the user is active; the media exists, is not soft-deleted and is not gated for them (`isGatedFor`, so the mature gate holds); the source is `ready` with a stored file; and either it is `public_domain` or `licensed` with `verified_by` and `verified_at` set, or it is `user_owned` with `owner_user_id` equal to the user and `verified_at` set. `external_link` is never streamable. Everything else is false. | A rule too strict hides a readable book; the tests cover each branch. |
| P9-R4 | `user_owned` uploads are verified for their owner by the upload itself (`verified_at` set, `verified_by` null). The plan's "system marker" cannot be a foreign key. They are private: the admin content page and admin preview never list or open them. | Admins cannot moderate uploads until reports exist (Phase 10). |
| P9-R5 | Admin verification: `VerifyContentSource::handle(source, admin, license, ?rightsHolder)` requires a non-empty license (at most 2,000 characters) and applies to public_domain, licensed and external_link only. Unverifying clears both fields and blocks access at once. Verifying a public-domain source that has a URL but no file queues `FetchContentFile` on the `ingestion` queue: it downloads from the provider's allowed hosts only, caps the size, checks the type with `finfo`, runs the archive guard and stores the file on the private disk at `content/pd/{ulid}`. | A file that fails to fetch leaves the source `failed` with a reason on the admin page. |
| P9-R6 | Gutenberg and Standard Ebooks are providers like the others (`gutenberg` and `standardebooks` in `config('bookflix.providers')`, disabled by default, with `external_sources` rows), so the existing sync jobs, rate limits, runs and the admin Sync page all apply. They implement a small `OffersContentFiles` interface; after each import `FetchProviderPage` records an **unverified** source (`access_type public_domain`, `format epub`, the feed's license text, the file URL, `external_key`). The plan's `ImportPublicDomainSources` becomes this hook. Import goes through `IngestionPipeline`, so ProhibitedContent and deduplication apply. | One interface check in `FetchProviderPage`. |
| P9-R7 | Feed scope (settled 2026-11-17: whole Gutenberg catalogue; Standard Ebooks public feed only). **Gutenberg** reads the official CSV catalogue (`/cache/epub/feeds/pg_catalog.csv.gz`), imports every `Text` row in bounded runs (a page is a slice of rows; the downloaded file is kept on the private disk for the run so pages do not download it again; the cursor is the `Issued` date, so later runs take new books only) and offers `/cache/epub/{id}/pg{id}-images-3.epub`. The CSV has no rights column, and a few Gutenberg books are still under copyright, so **`FetchContentFile` reads that book's official RDF record (`/cache/epub/{id}/pg{id}.rdf`) before downloading and fails the source unless `dcterms:rights` says public domain**. **Standard Ebooks** reads the public Atom new-releases feed (the 15 newest) and keeps the `<rights>` text as the license; no member feed. Type: Gutenberg LoCC `P*` or a fiction bookshelf, and Standard Ebooks fiction subjects, map to `novel`; the rest to `nonfiction`. | About 75,000 new stories, each one classified and embedded by the existing jobs; the first runs take days at the provider's rate. Sources stay unverified until an admin verifies them. |
| P9-R8 | Streaming: `GET reader/stream/{source}` under `auth`, `verified`, `reader`, `signed:relative` and a throttle. The URL comes from `ContentUrl::for(user, source)`, lasts `reader.url_ttl_minutes` (10) and is bound to the signed `user`. The handler re-checks the gate and that the signed user is the one signed in. Ranges: one range gives 206 with `Content-Range`; an unsatisfiable or malformed range gives 416; several ranges get the whole file with 200 (allowed by RFC 9110). Responses carry `Content-Disposition: inline`, `nosniff`, `Cache-Control: private, no-store` and the type from the stored format. A missing file gives 404. Admin preview is a separate signed route under `/admin`. | Relative signatures do not bind the host; the user binding and the 10-minute expiry carry the security. |
| P9-R9 | CSP (settled 2026-11-17: nonce plus `'unsafe-eval'`): a `SetContentSecurityPolicy` middleware on the `web` group calls `Vite::useCspNonce()` and sends `default-src 'self'; script-src 'self' 'nonce-…' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; font-src 'self' data:; connect-src 'self'; media-src 'self'; worker-src 'self' blob:; frame-src 'self' blob:; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`. `'unsafe-eval'` stays because Alpine's standard build needs it: `csp_safe` would mean rewriting about 130 expressions and is a separate task. With Vite running hot (local only) the dev server's origin is added. The debug error page is left without a CSP so it still renders locally. `bookflix.csp.enabled` and `bookflix.csp.report_only` come from the environment. The browser suite must stay green under it. | `'unsafe-eval'` leaves Alpine-attribute injection open; nonces still block injected `<script>` and inline handlers. |
| P9-R10 | Archive guard (from 9.5, built early): one `ZipGuard` used by CBZ, EPUB and CBR conversion. It rejects `..`, absolute paths, backslash paths, symlinks (from external attributes), more than `reader.archive.max_entries` (2,000), more than `max_uncompressed_mb` (1,024) in total, and a ratio above `max_ratio` (100). It reads central-directory sizes and counts actual bytes while streaming. CBZ pages are image entries (`jpg jpeg png webp gif`), natural-sorted, skipping `__MACOSX` and dotfiles, streamed from the zip with no extraction to disk, and typed with `finfo`. | A real comic over 2,000 pages or 1 GB is refused; the limits are config. |
| P9-R11 | Q11 / CBR (settled 2026-11-17: allow `unar` and `bsdtar`). Both are system programs run through `Process`, never bundled (`unar` LGPL-2.1, `bsdtar`/libarchive BSD-2-Clause, approved by the user as exceptions to the licence list). `CbrConverter` uses `reader.cbr.unar_path`, else `reader.cbr.bsdtar_path`; whichever exists runs with a timeout into a fresh temp directory, then the pages are checked like any CBZ (`ZipGuard` limits, image entries only, no links) and rebuilt as a CBZ. With neither installed, CBR is refused at upload: "This server reads CBZ, not CBR. Convert the file to CBZ and upload it again." | `bsdtar`'s RAR5 support is partial; such a file fails with a clear reason and the original is kept. |
| P9-R12 | Uploads (9.7): `UploadContentSource::handle(User, Media, UploadedFile)` checks the type with `finfo` plus magic bytes (EPUB: a zip whose first entry is an uncompressed `mimetype` of `application/epub+zip`, with `META-INF/container.xml`; PDF: `%PDF-`; CBZ: a zip with at least one image page), the per-format size caps, the 2 GB per-user quota (sum of `byte_size`), and that the media is visible to the user. It stores the file at `content/{user_id}/{ulid}` on `reader.disk` (private by default), keeping the client name only in `original_name`. Rate limit: 10 uploads an hour per user. Deleting a source deletes its file; the purge command deletes a user's uploaded sources and files before the user. The Livewire upload rule and PHP's upload limits must allow the caps; the screen, its route and the Livewire config come with the signed-off design. | Large uploads need `upload_max_filesize` and `post_max_size` raised at deploy. |
| P9-R13 | Progress (with 9.3): readers save through a `ProgressWriter` that calls `LogProgress` with the source. To keep a reader from flooding the history and interactions, a save within 10 minutes of the last one for the same source extends that session instead of appending one, and `reading_progress` is recorded at most once per session. This changes `LogProgress`'s signature (an optional source), not its manual-log behaviour. It is decided in detail with 9.3. | Session lengths are approximate within the 10-minute window. |
| P9-R14 | pdf.js range requests outlive a 10-minute URL. The PDF reader asks the page for a fresh signed URL before the old one expires (9.4). | A tab left open past expiry needs one refresh request. |
| P9-R15 | New dependencies: none for the backend. Readers: `foliate-js` 1.0.1 (MIT, npm) and `pdfjs-dist` 6.5.438 (Apache-2.0, released 2026-11-01), both named in the plan, pinned exactly. | None. |
| P9-R16 | foliate-js sets `sandbox="allow-same-origin allow-scripts"` on its iframes (`paginator.js`, `fixed-layout.js`) because of WebKit bug 218086. The user's rule is a sandbox without `allow-scripts`, so a small Vite transform in `vite.config.js` rewrites both to `allow-same-origin` at build time (no new dependency), and a browser test asserts it. The page's CSP, which the blob documents inherit, is the second layer. | On Safari, links inside a book (footnotes, in-text links) don't respond. Paging, the keyboard, contents and settings run in the page, outside the iframe, and work everywhere. |
| P9-R17 | The reader page (`reader.show`) adds `blob:` to style-src and font-src (EPUB stylesheets and fonts are blob URLs in the iframe) and, only if pdf.js needs it, `'wasm-unsafe-eval'` to script-src. pdf.js runs with `isEvalSupported: false` and its worker from `/build` (same origin). | A wider policy on one route. |
| P9-R18 | Uploads up to 500 MB go through Livewire's temporary upload on the private local disk; `config/livewire.php` carries the full `temporary_file_upload` block with that size. PHP `upload_max_filesize` and `post_max_size` must allow it at deploy. | Large uploads fail with PHP's limit until the server allows them. |
| P9-R19 | `FetchContentFile` follows no redirects. Standard Ebooks serves feed downloads directly (checked 2026-11-17: 200, `application/epub+zip`); Gutenberg's `/cache/epub/` files are served directly too. | A provider that starts redirecting fails with "The file is no longer at its address." until the rule is revisited. |
