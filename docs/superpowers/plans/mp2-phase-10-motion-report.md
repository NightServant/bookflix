# Phase 10: Motion, Design-Tells Audit and Final Report Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put every animation in Bookflix on shared duration and easing tokens, add the hover/press, micro-interaction, loading, skeleton, reveal, dialog and page-transition behaviour the brief's Part G asks for, then write the design-tells report (H) and the cumulative ten-phase report (I).

**Architecture:** Duration, easing and scale values live as CSS custom properties in `resources/css/app.css` and as a matching `MOTION` object in `resources/js/motion.js`; a Pest unit test reads both files and fails when they drift or when a literal duration appears outside the tokens. Behaviour is added as small CSS utilities and Blade components (`x-skeleton.*`, `x-save-check`) plus Livewire 4's own `data-loading` attribute and `wire:transition.navigate`, so no new dependency is needed. H and I are documentation tasks with a Pest lint test each.

**Tech Stack:** Tailwind 4 (`@utility`, `@theme`), Alpine 3 + `@alpinejs/ui`, Motion 12.43 (`animate`, `inView`, `scroll`), Livewire 4.4.8, Flux 2.21 free, Pest 5 + browser plugin.

**Spec:** `docs/superpowers/specs/2026-11-26-cleanup-brief.md` Parts G, H, I; `docs/superpowers/plans/2026-11-26-bookflix-masterplan-2.md` Part F "Phase 10", D2-22, Part G.
**Branch:** `mp2-phase-10-motion-report` · **Ledger:** `docs/superpowers/plans/mp2-phase-10-ledger.md` (the old `phase-10-ledger.md` is from Masterplan 1; leave it) · **Depends on:** all of 1 to 9. ## Global Constraints

Every Global Constraint in the masterplan applies. Phase-specific:

- Durations: micro `--motion-fast` 150ms (range 100-150), UI `--motion-base` 250ms (200-250), pages and modals `--motion-slow` 300ms (250-350). Nothing a user triggers runs longer than 350ms.
- Easing: `--ease-out-bookflix: cubic-bezier(0.2, 0, 0, 1)` for everything that enters or responds; `--ease-in-out-bookflix: cubic-bezier(0.4, 0, 0.2, 1)` only for cross-fades.
- Only `transform`, `opacity`, `color`, `background-color`, `border-color` animate. Never `width`, `height`, `max-height`, `grid-template-rows`, `margin`, `padding`, `top`, `left`, `inset`.
- Scale values: cover tile hover `--lift-scale: 1.04` (allowed 1.03-1.05); button press `--press-scale: 0.98`.
- Skeletons appear after `--skeleton-delay: 300ms`; below that nothing shows.
- Reveal distance 8px (allowed 8-16px), once, 250ms.
- Under `prefers-reduced-motion: reduce`: every transition is `0s` and every animation is off or a single-frame; parallax, reveals, hover scale and press scale do not run. Computed styles prove it.
- No new colour: the navigate progress bar uses an existing token. Red `#e50914` stays CTA-only (`RedForCtasOnlyTest`); no shadows beyond the three tokens.
- H changes nothing beyond Part G. No font is added or changed; the font finding is a proposal only. No dependency is added (D2-7): a smooth-scroll or parallax library is "Needs decision", not installed.
- Copy: plain, no heavy em-dash use, no cursive fonts. Report prose follows the same rule.

## Review Focus

1. **A reduced-motion reader still sees movement.** A plain `transition-*` class without `motion-safe:` (five exist today), an inline style left by Motion, or a CSS animation outside a reduced-motion block keeps moving. → Task 10.1 (browser computed-style test with `reducedMotion: 'reduce'`) and 10.6 (parallax off).
2. **A skeleton flickers or shifts the page.** It shows for a fast response, or is a different height from the content it stands in for, so the page jumps when the real content lands. → Task 10.5 (delay test, height parity) and Task 10.6 (CLS check on home and landing).
3. **A double submit.** A Livewire action button stays clickable while its request is in flight, so a slow connection saves, reports or deletes twice. → Task 10.4 (static scan of every `wire:click` and `wire:submit`, plus a computed-style check of `[data-loading]`).
4. **A hover-only affordance with no keyboard or touch path.** The tile's dismiss button, the cover zoom and the Top 10 title appear only on `:hover`. → Task 10.2 (focus-visible and `pointer-coarse` assertions on tiles and buttons).
5. **A dialog or drawer loses focus or leaves the page scroll-locked.** Focus does not enter, does not return to the trigger, or the transition is skipped under reduced motion and the body stays locked. → Task 10.7 (one modal and one drawer, focus in and back, body scroll restored, reduced-motion variant).

## Rulings

- **P10-R1 One token set, `slow` becomes 300ms; no new `micro` name.** `--motion-fast` already sits in the micro range, so no `--motion-micro` is added. Cost if wrong: low; a rename is a find and replace.
- **P10-R2 Ambient and decorative loops are exempt from the 350ms cap, entrances are not.** Exempt (listed in the test's allow-list by selector): `landing-float`, `landing-drift`, `reader-spin`, `book-scene.js` turn (900ms, WebGL). Not exempt: `landing-arrive` (900ms today) becomes `var(--motion-slow)` with a `calc(var(--i) * var(--motion-stagger) + 120ms)` delay. All exempt items are already off under reduced motion; the test asserts that. Cost if wrong: low; the hero arrival feels quicker.
- **P10-R3 A global reduced-motion rule backs up the per-element ones.** `@media (prefers-reduced-motion: reduce) { *, ::before, ::after { transition-duration: 0s !important; animation-duration: 0.01ms !important; animation-iteration-count: 1 !important; scroll-behavior: auto !important } }` in `@layer base`. This catches the five unguarded `transition-colors` and third-party CSS (Flux). Cost if wrong: a spinner that should keep turning stops; spinners already stop (`reader-spinner`, Flux indicator), and the busy state is also conveyed by `aria-busy` and the disabled look.
- **P10-R4 Livewire 4 already marks the element that fired a request with `data-loading` (`livewire.esm.js:16908`).** One global rule (`[data-loading] { pointer-events: none; opacity: 0.6 }`) gives every action trigger a disabled look with no per-view edit. The spinner comes from Flux buttons and `x-cta` (`data-flux-loading-indicator`, built in) and from an explicit `wire:loading` spinner on non-button triggers. The scan test passes a trigger if it is a Flux/`x-cta` button, or carries `wire:loading` / `wire:loading.attr`, or is allow-listed with a reason. Cost if wrong: a trigger that only dims is quieter than a spinner; the scan still names every plain `<button wire:click>`, which gets an explicit spinner.
- **P10-R5 Skeleton delay is pure CSS (`animation-delay: var(--skeleton-delay)` from `opacity: 0`), one mechanism for Livewire placeholders, `wire:loading` blocks and navigation.** Livewire's `wire:loading.delay.long` is also 300ms, but only covers one of the three cases and would need a second mechanism. Cost if wrong: a skeleton in the DOM at opacity 0 is announced to screen readers; it is `aria-hidden="true"` with a sibling `role="status"` "Loading".
- **P10-R6 Navigate progress bar uses `var(--color-ink)` (white).** Brand red is for CTAs only, `--color-link` blue is for text links, `--color-accent-electric` is the focus ring colour and would read as a focus indicator. White is the one neutral on the black canvas with 21:1 contrast, and the header is surface-deep, so the bar is visible at the top edge. Livewire writes the value into `:root{--livewire-progress-bar-color: ...}`, so a `var()` string works. Cost if wrong: one config line.
- **P10-R7 Cross-fade between pages uses `wire:transition.navigate` on `<body>` content wrapper, not a custom `startViewTransition`.** Livewire 4.4.8 implements it (`transitionPageSwap`, `livewire.esm.js:15200`), skips under reduced motion and when a modal is open. The existing hero-cover view transition (`components.js:152`) keeps working because Livewire's own transition is skipped while a view transition is already running; Task 10.7 checks that by test. Cost if wrong: if the two clash, the hero morph wins and the cross-fade is dropped on that one link.
- **P10-R8 The FAQ panel stops animating `grid-template-rows` (a layout property).** It opens instantly and its text fades in (opacity, 250ms); the plus icon still rotates. This changes Phase 4's CSS; Task 10.6 re-reads the file first. Cost if wrong: the accordion feels less smooth; a height animation can come back through the `grid-template-rows` trick only if the owner accepts a layout animation, which the brief forbids.
- **P10-R9 Parallax is on the landing hero stage only (`.landing-stage`), not on Home's `<x-hero>`.** The brief allows one. The landing stage has no `transform` of its own (its books use `translate`/`animation` on children), so a scroll-driven `translateY` is safe. Cost if wrong: Home's hero is still. Motion's `scroll()` is already installed, so no dependency.
- **P10-R10 Reveals keep two places: shelf tracks (`shelf.blade.php:81`) and the landing "scattered" list (`scattered.blade.php:37`).** The four others (`series/⚡show:154`, `discover/⚡index:283` and `:327`, `stories/⚡show:349`) are removed: they re-run on every filter change or are above the fold, and reveal-everything is a named design tell. Cost if wrong: re-add one attribute.
- **P10-R11 Field valid confirmation is a green check (`text-success`, `#46d369`) only on fields that validate live (`wire:model.blur`/`.live`) and have passed with a non-empty value.** Colour is never the only cue: the check is an icon, the field sets `aria-invalid="false"`, and an `sr-only` "Looks good" is in the field's `aria-describedby`. Cost if wrong: a few fields lack the check; none lose validation.
- **P10-R12 The favourite heart already swaps outline to solid (`⚡library-controls.blade.php:318`).** The fill gets a 150ms pop (`scale 0.8 to 1`) on `aria-pressed="true"`; nothing else about favourites changes. Cost if wrong: none.
