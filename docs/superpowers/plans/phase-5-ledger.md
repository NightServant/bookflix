## Accepted deviations
- 5.1
  - Plan file list: `Media` is not modified (no relation was needed); `LibraryEntry::scopeVisibleTo` carries the mature gate for entries instead.
  - `user_interactions.value` is `float(24)`, which is PostgreSQL `real` (Laravel's schema builder has no `real()`).
  - `RecordInteraction` re-checks the reader's opt-out when it runs, and skips a deleted reader: an event queued before an opt-out must not be written afterwards. Under the `sync` queue this adds two queries, so the story page budget tests fake the queue (the queued view is not page work) and their budgets grow by exactly one query each, the reader's library entry for the controls (25 to 26, 21 to 22).
  - `SearchLogger::sessionHash()` and `ranInThisSession()` were added so the story page compares against the same keyed hash the logger stores (revision item 10).
  - The story page test forces the session id through the session cookie (a 40 letter id), so the real `?sq=` check is exercised, not just the refusal.
  - Add to Library path (revision item 5):
    - `<x-library-add>` is the one button for `<x-hero>` and `<x-story-summary>`. It renders only for a signed-in reader (`@auth`), replacing the `Route::has('library.store')` gates, and raises the `library-add` event.
    - The hero button is also a form that posts to `library.store` (no-JS fallback). The preview card's button has no form (`:form="false"`), because the card only exists after scripts clone its `<template>`, and a form per tile would add a CSRF token to every tile.
    - `<livewire:library-listener>` lives in `layouts/app/header.blade.php` and hides itself (`<div hidden>`). It applies the same rules as the route: auth, verified, a 60 per minute limit under its own key `library-add:{id}`, and `Media::visibleTo`. A story behind the mature gate is refused with a danger toast, exactly like an unknown id.
    - `library.store` uses `throttle:60,1,library`. The prefix matters: Laravel's numeric throttles share one counter per reader across routes, so without it the cover proxy's hits would count against adding stories.
  - The story page's CTA row now holds `<livewire:library-controls>` (add, a status menu with 44px items, a favorite toggle, remove inside the menu) next to a now quiet "See the series". The page has one primary button.
  - The Flux toast's close button had no accessible name, which failed the axe audit on any page showing a toast (admin toasts included). `resources/views/flux/toast/index.blade.php` is a copy of the vendor file with `aria-label` added and the Blaze fold directive left off (the label is translated at runtime).
  - `ToggleFavorite` on a story not in the library fires `LibraryChanged` twice (the add, then the favorite). Harmless for cache invalidation.
  - Browser tests that used `enableLibraryRoute()` now sign a reader in (the buttons are for readers). The Pest helper was removed.

### Batch C (5.5, 5.6)
- 5.5
  - Plan file list: the migration is `2026_10_29_000006_create_ratings_table.php` (primary key `(user_id, media_id)`, `media_id` indexed, timestamps). `Rating` has no auto key (saved by both halves, like `ReadingProgress`) and a factory; `User::ratings()` was added.
  - Revision item 1, as built:
    - `App\Catalog\MediaRatings::blend(Media, bool $clearEmpty = false)` is the old `recordMetrics` blend moved verbatim (counts add up, the average is weighted by each source's count, a source without one weighs 1, `locked_fields` respected). `IngestionPipeline` calls it and its test is unchanged. Deviation: `$clearEmpty` is new. The job passes it, so removing the last rating (with no provider rating behind it) empties `average_rating` and `ratings_count`; the pipeline does not pass it, so its behaviour for a media with rating columns and no rating metrics is exactly as before.
    - `RecalculateMediaRating` runs in a transaction with the media row locked, reads the ratings of `User::active()` readers (count and mean in one query), upserts `ratings_count` and `average_rating` (round(mean / 2, 2)) for the `bookflix` source, or deletes the two rows when there are none, then blends. A deleted or unknown media id is skipped.
    - The `bookflix` source follows the `isbn` pattern: made on first use (`MediaRatings::readersSource()`, `createOrFirst`, name "Bookflix readers", `enabled` false), not in `ExternalSourceSeeder`. `ExternalSource::SYNTHETIC` lists both synthetic keys and `scopeProviders` excludes them, which keeps `bookflix` out of the admin provider list, its toggle, the sync command and the admin dashboard count. `PopularityScorer` leaves the source's rows out of the ranking (`config('bookflix.popularity.weights')` is keyed by metric, not by source, so exclusion is the way to give it no weight). Phase 6 can lift that.
  - `RateMedia::handle` upserts in one statement (two racing clicks cannot collide on the key). It records the `rating` signal and fires `LibraryChanged` only when the score changed (a double click is not a second signal); it queues the job every time (idempotent, and it heals an aggregate a failed run left). `forget` does nothing for a rating that is not there. Rating does not touch the library. Not throttled (as F7).
  - Controls: `public mixed $rating` (the model; it comes from the client, so `saveRating` validates `required|integer:strict|between:1,10` before the action and only ever writes the signed-in reader's row), `saveRating()` and `clearRating()` both start with `reader()` and `story($user)`. Stars are 28px glyphs in 44 x 48px cells; each half is a 24px wide, 44px tall target (so the 24px axe target size rule holds without 22px halves). `wire:model` is deferred; the component dispatches a bubbling `rated` event with `{ value }` and the controls call `saveRating()` or `clearRating()` on it. A click, Space and the Clear button save at once; arrows, Home and End (wrapping, as the view toggle) save after 700 ms of quiet or when focus leaves the group, so walking along the stars is one save. Delete and Backspace clear. Empty stars are `text-ink-muted` (the 3:1 rule for a control; the display's hairline stars are decorative).
