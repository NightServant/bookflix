## Accepted deviations
- 5.1
  - Plan file list: `Media` is not modified (no relation was needed); `LibraryEntry::scopeVisibleTo` carries the mature gate for entries instead.
  - `user_interactions.value` is `float(24)`, which is PostgreSQL `real` (Laravel's schema builder has no `real()`).
  - `RecordInteraction` re-checks the reader's opt-out when it runs, and skips a deleted reader: an event queued before an opt-out must not be written afterwards. Under the `sync` queue this adds two queries, so the story page budget tests fake the queue (the queued view is not page work) and their budgets grow by exactly one query each, the reader's library entry for the controls (25 to 26, 21 to 22).
  - `SearchLogger::sessionHash()` and `ranInThisSession()` were added so the story page compares against the same keyed hash the logger stores (revision item 10).
  - The story page test forces the session id through the session cookie (a 40 letter id), so the real `?sq=` check is exercised, not just the refusal.
  - Add to Library path (revision item 5):
    - `<x-library-add>` is the one button for `<x-hero>` and `<x-story-summary>`. It renders only for a signed-in reader (`@auth`), replacing the `Route::has('library.store')` gates, and raises the `library-add` event.
    - The hero button is also a form that posts to `library.store` (no-JS fallback). The preview card's button has no form (`:form="false"`), because the card only exists after scripts clone its `<template>`, and a form per tile would add a CSRF token to every tile.
    - `<livewire:library-listener>` lives in `layouts/app/header.blade.php` and hides itself (`<div hidden>`). It applies the same rules as the route: auth, verified, a 60 per minute limit under its own key `library-add:{id}`, and `Media::visibleTo`. A story behind the mature gate is refused with a danger toast, exactly like an unknown id.
    - `library.store` uses `throttle:60,1,library`. The prefix matters: Laravel's numeric throttles share one counter per reader across routes, so without it the cover proxy's hits would count against adding stories.
  - The story page's CTA row now holds `<livewire:library-controls>` (add, a status menu with 44px items, a favorite toggle, remove inside the menu) next to a now quiet "See the series". The page has one primary button.
  - The Flux toast's close button had no accessible name, which failed the axe audit on any page showing a toast (admin toasts included). `resources/views/flux/toast/index.blade.php` is a copy of the vendor file with `aria-label` added and the Blaze fold directive left off (the label is translated at runtime).
  - `ToggleFavorite` on a story not in the library fires `LibraryChanged` twice (the add, then the favorite). Harmless for cache invalidation.
  - Browser tests that used `enableLibraryRoute()` now sign a reader in (the buttons are for readers). The Pest helper was removed.
- 5.2
  - Sorts: only `added` and `title` exist (`SORTS`). Unknown values fall back to `added`. `last_read` needs `reading_progress.last_read_at` (5.4) and `rating` needs `ratings` (5.5); both tables are not created here. The plan's two sort test cases belong to those tasks. Wire them in `entries()` and add the value to `SORTS` and the sort `<select>`.
  - Layouts: the plan's `view` (`grid|shelves`) became `grid|list|shelves` (C7 #7). `<x-view-toggle>` gained a `shelves` prop (a third, 44px option with the Lucide `library` icon, imported with `flux:icon`).
  - The shelves view groups by `ClassShelves::forMedia` and adds a "Not Yet Shelved" row for stories with no public primary class, because the shelves leave those out and the library must never hide an entry. `<x-class-shelves>` gained a `links` prop; the library turns "See all" off, since the class page lists the whole catalog.
  - The shelves view loads up to 200 entries a page (the grid and list 24).
  - `<x-result-row>` gained an optional slot, a page's own line under the facts. The library puts the status, the favorite heart and "Added 3 days ago" there.
  - The page reads its data through computed properties (`entries`, `statusCounts`, `typeOptions`, `shelves`, ...), the way the Search and Discover pages do, not through view data. Tests read `->instance()->entries`.
  - `statusCounts` follow the format and favorite filters (and show every status, zero included), so a tab's number is what the tab shows.
  - The mature gate (revision item 2, D-35) is `LibraryEntry::visibleTo`, which goes through `Media::unmerged()->visibleTo()`. It covers the list, the counts, the format list and the shelves. Gated entries stay stored. The page does not hint that some are hidden. The test uses `Genre::factory()->mature()`, and one with `User::factory()->showsMature()`.
  - Gate `view-library` is defined in `AppServiceProvider` (owner, or public and not deactivated).
  - Navigation (revision item 6): Library is in `config('bookflix.navigation')` for the desktop header and the phone bar (Home, Discover, Search, Library, Profile). Its `active` patterns include `collections.*` and `history.*`, so those pages keep it current.
  - `<x-library-tabs current="…">` draws the Library, Collections and History tabs under the page title. A section whose route does not exist yet is left out, and a lone Library draws nothing. 5.3 and 5.6 only need to put the component in their header and pass their own route name.
  - Discover's quick link "Continue reading" (it pointed at a `library` route that never existed) is now "My library" → `library.index`.
  - The page is `flush`: a `bg-surface-deep` header band plus `px-gutter` content, so the shelves can bleed like Explore's.

### Batch B (5.3, 5.4)
- 5.3
  - Plan file list: the migration is `2026_10_29_000004_create_collections_tables.php`. `collection_items` also has `note` (A6, no UI yet) and timestamps. The writes live in four actions the plan did not list (`CreateCollection`, `AddToCollection`, `RemoveFromCollection`, `MoveCollectionItem`), because the page and the story controls both write.
  - Collections is a tab under Library (`<x-library-tabs current="collections.index">` on the index and on the page), not a bar item (revision item 6). The tab shows up in the header of the library page by itself, as F5 said.
  - Slugs: unique per owner, counter on a clash (`favorites`, `favorites-2`, a name with no letters becomes `collection`), a race on the unique key retries the next slug. The slug stays when the name changes, so links keep working. The route resolves own, then editorial, then a public collection of an active reader (lowest id first). A link to a staff pick carries `?editors=1`, so a reader's own collection of the same name cannot take its place (deviation: the plan says "ambiguous slugs prefer the viewer's", which would send a reader to their own list from an editor's link).
  - Reordering: `wire:sort` exists in Livewire 4.4.8 (SortableJS; item id and index are passed to the handler). The drag is by a handle (hidden on phones, where there are the buttons). Every row has move up and move down buttons that call the same `reorder` action with the same two values, so reordering works by keyboard; the focus goes back to the moved story's button (the first row has no up and the last no down, so it goes to the one it has), and a polite live region says "X moved to position 2 of 5". The position is counted among the stories the reader may see; a story hidden by the mature gate keeps its seat between its neighbours (`MoveCollectionItem`).
  - Limits: names 100 characters, descriptions 500, at most `config('bookflix.collections.max_items')` (300) stories per collection, error key `collection`. The page lists every story at once, so it stays bounded. Not in the plan.
  - The owner adds stories on the page from a search (`HybridSearch`, so the mature gate and its 120 per minute throttle apply) or, with nothing typed, from the library's latest stories not yet in the collection. A viewer who is not the owner gets a grid of covers and none of the edit controls. Admin only: the "Show as an editor pick" switch (`access-admin`); any other reader's value for it is ignored on save.
  - Mature gate (revision item 2): `CollectionItem::scopeVisibleTo` (as for `LibraryEntry`), `CollectionPreviews` (counts and covers for a list of collections in two queries) and `EditorialCollections` all go through `Media::unmerged()->visibleTo()`. A staff pick with nothing the reader may see is left out of every list. The index also lists the staff picks ("Picked by Our Editors", not the reader's own).
  - Editorial banner row (C7 #4): `EditorialCollections::shelves()` gives `Shelf` objects (`Shelf` gained `description` and `href`), shown by `<x-editorial-shelves>` on Discover (after the quick links) and on Home (between New Releases and Explore by Subject): one shelf per collection, the name as the title, "Staff pick" as the eyebrow, "See all" opening the collection. Two at most. They are rows, never a grid. Not cached (two queries plus the tiles, none when there is no staff pick); the story picks of Home keep their ten minute cache.
  - `library-controls`: an "Add to collection" menu (the reader's 50 most recently changed collections as checkbox items that add or remove the story, and "New collection", a dialog that creates it and adds the story). The story page budgets grew by one query, the collections (27 and 23). `<x-library-controls>` in the plan is the `<livewire:library-controls>` that exists.
  - Tests that had to change: Discover's quick links now list "My collections" (history still waits for 5.6); the "library alone has no tabs" test strips the router down to the library route (every section is a real page now); the story page browser test checks the open menu only (`ui-menu:popover-open`), since the page now has two menus. Pest helpers `matureStory()` and `collectionOf()` are in `tests/Pest.php`.
- 5.4
  - Plan file list: the migration is `2026_10_29_000005_create_reading_tables.php`. `reading_progress` has the composite primary key `(user_id, media_id)` and a CHECK of 0 to 100 on `percent`; the model has no auto key and saves by both halves (`setKeysForSaveQuery`). `reading_history` has an `id`.
  - `LogProgress` follows the plan with these readings of it: a log on a wanted, paused or abandoned story makes it Reading (not only the first log); `reading_start` is recorded only on the first log of a story that was not yet Reading (a story set to Reading by hand had its start stamped then, as `SetLibraryStatus` does, and records no event); `reading_complete` is recorded only while `completed_at` is empty (stricter than "not already completed", so a story the reader flipped back to Reading and finished again counts once, Review Focus #5); a log on a completed story below 100 leaves it Completed; a story logged straight to 100 records start, progress and complete in that order; a move back records a zero delta, never a negative one. The percent is rounded to two decimals after it is checked (99.999 stores 100.00 and completes). Page and chapter are the latest log's, so a percent-only log clears them; the form shows the previous ones as placeholders.
  - Two logs of one story at once are serialized on the library row (`lockForUpdate`), and the signals are recorded after the transaction.
  - `library-controls`: a "Log progress" button (it reads "64.5% read" once there is progress) opens a dialog with percent, chapter, page and minutes (`pageNumber` is the property, not `page`). The entry query joins the progress in, so the controls still ask one query of `user_library` (the test for it holds) and none extra of their own.
  - Library page (5.2's F4): `last_read` is a sort (unread last, ties by title; the plan's test case is in `LibraryPageTest`). Grid tiles show the progress bar of a story under way (not a finished one, not one at 0), list rows say "42.5% read", the shelves view shows none. One extra query for the page's progress.
  - Continue Reading: `ContinueReading::shelf()` lists the reader's entries at Reading, last read first, then those with no progress logged yet; it carries `progress_percent`, `progress_chapter` and `progress_page` on each story for the tile ("Chapter 7" or "Page 120" as its reason line). Home renders it first, not lazily (it is the reader's own and a skeleton would shift the page), and "See all" opens the library at Reading sorted by last read. With nothing in progress it is one cheap query and nothing on the page.
  - Decision kept: `?sq=` stays un-emitted (Phase 4 review R11), and no link got a tracking parameter.
- Browser tests added: `tests/Browser/CollectionsTest.php` (the pages on desktop and phone with the shared checks, 44px targets, the keyboard reorder with the focus assertion, a drag by the handle, removing and adding, the collection menu and the new collection dialog, the progress form with the audit, Continue Reading on Home).
