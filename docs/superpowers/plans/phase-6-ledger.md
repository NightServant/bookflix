### Accepted deviations (6.0)
- Enum-like columns are strings, not DB enums (like `user_interactions.event`), so later values (`popular_with_followed`, `llm`) need no migration. `ModelKind` has no `llm` yet (Phase 11).
- `ml_job_runs.started_at` defaults to the creation time (a queued run has no separate start); no timestamps columns.
- `media_similarities` has a CHECK that a media is never its own neighbor and an extra index on `similar_media_id` (cascade deletes).
- The seeder skips a name that already has any version, so a re-seed never resets edited or replaced weights. `interaction-weights` stores the rating formula as `rating_midpoint` 5.5 and `rating_scale` 1.2, plus `half_life_days` 90.
- `startJob` sends `{"params": {}}` (an object, never a list) and `MlClient` run ids are URL-encoded.
- The plan's test for `contract()` named `ml/tests/expected_columns.json` columns `published_on`, `alternative_titles` etc.; `merged_into_id` was added to `media` so Python can skip merged media like the view does.
- Local setup note: `public/build` is git-ignored, so a fresh worktree needs it copied from the main checkout before the full PHP suite passes. `composer test` also needs `COMPOSER_PROCESS_TIMEOUT=0` here: the suite takes over 300 s.

### Accepted deviations (6.1, 6.2)
- Ruff's `E501` is ignored in `ml/pyproject.toml` (SQL strings and docstrings); `ruff format` still wraps code. mypy now checks `bookflix_ml` too, with `ignore_missing_imports` for sklearn, implicit, scipy, joblib, boto3 and pgvector (no stub packages added).
- `implicit.nearest_neighbours.bm25_weight` gives an item read by most users an idf of 0 and then NaN similarities on small data, so `item_cf` applies its own BM25 (same K1 and B, idf `log(1 + (N - df + 0.5) / (df + 0.5))`) before `CosineRecommender`.
- The interaction weights use the keys 6.0 stored (`rating_midpoint`, `rating_scale`, `reading_progress` 0.05 per point, `half_life_days`), not the plan's `reading_progress_per_percent`/`rating_center`; `DEFAULT_WEIGHTS` mirrors the config and fills any missing key.
- `train_lsa` retries with `min_df=1, max_df=1.0` when the plan's `min_df=2, max_df=0.6` leaves no vocabulary (two-document corpora); no usable text raises `NotEnoughData`.
- `JobRunner(inline=True)` exists for tests; `JOBS` holds only registered names, so a name the plan lists but later tasks add answers 404.
- Version strings are UTC timestamps with microseconds (`20261104T120000123456Z`); `registry.*` never commits, the job decides the transaction. `ml/Dockerfile` now copies `bookflix_ml`. No PHP changes.

### Accepted deviations (6.3)
- Revision item 4 overrides the plan's ordering. The blend is `popularity_score + w × trending_percentile`, `w` = 0.05 (config), with `trending_percentile` the `cume_dist()` (not `percent_rank()`) of `trending_score` among media with interactions in the last 30 days, 0 for the rest: `percent_rank` gives the least active of them 0, the same as no activity, so a single view would not count. Tie-breakers stay `ratings_count`, `published_on`, `id`.
- The percentile is a new column of the view (new migration that recreates it) rather than a window over all media per request. The scope adds no `select`, so models loaded through it carry the view's columns as extra attributes.
- `build-similarities` takes the item_cf neighbors from the stored `item-cf` artifact instead of recomputing from `fetch_interactions`.

### Accepted deviations (6.4)
- Sources hold their code in `app/Discovery/Recommendations/` (revision item 6), plus a `GenreAffinity` helper (top three genres from chosen genres plus seed strengths) shared by `PopularInGenresSource` and `ExplorationSource`. `Sources\Source` has a final-style `candidatesFor` (limit, `take`) over an abstract `gather`, an `eligible()` query (unmerged, `visibleTo`, not in the library, not dismissed; soft deletes via the model) and `neighborsOf()` (joins `model_versions.status = 'active'` and `kind = method`).
- `Media::scopeTrending` now reads its blend from `Media::TRENDING_BLEND` / `Media::trendingWeight()`, so `TrendingSource` selects the same expression it orders by instead of copying it. `TrendingSource` divides by the best blend in the set; an all-zero blend falls back to position scores (1 down to 1/n).
- `CollaborativeSource` and `ContentSimilarSource` both multiply the neighbor score by the seed strength (the plan spells it out only for content); collaborative sums, content takes the best seed. `DeweySimilarSource` looks at the 200 most popular titles of the seeds' divisions, then scores them; seeds classified at the top level only are skipped (no division).
- `ExplorationSource` draws from the 500 most rated titles per tier (well-rated, any rated, any), so the pool stays bounded on a large catalog; the randomizer is the container's `Random\Randomizer`, and tests pass a seeded one. Its score is `average_rating / 5`.
- `EditorialSource` and the `TrendingSource` fallback score by position. No source selects `cover_url`, so nothing needed `Media::displayCover`.
- The reader-sees-only-active-versions test lives with `ContentSimilarSourceTest`, so it is in the 6.4 commit, not the F6 fix; the F6 commit carries the Python tests and a schema-level PHP test.
- Test helpers `activeVersion`, `similar`, `libraryEntry`, `dismissed` are in `tests/Pest.php`.

### Accepted deviations (6.5 to 6.7)
- Popularity feature is `min(1, popularity_score + trending_weight × trending_percentile)` (the `Media::TRENDING_BLEND` expression, revision item 4), not `popularity_percentile`; novelty is `1 - popularity`. None of the eight features reads `average_rating`, so the 0-5 scale did not come up in this batch. Freshness uses `max(0, age)`, so a future release date counts as 1.
- Collaborative score is the strength-weighted mean of the item_cf neighbor scores of the seeds that lead to the title (the plan's `Σ score × strength / Σ strengths`, read over the connecting seeds), not a sum capped at 1 as `CollaborativeSource` does. Content takes the max over the `lsa` and `embedding` neighbors. Both read only active versions (`model_versions.kind = method`).
- Preference counts `user_preferences` (genre, theme, media_type, creator) plus the strength of seeds sharing a genre, over the best candidate's; trope and demographic are not read.
- `Diversifier` and `ExplorationInjector` need no container wiring (`new` works); `Diversifier` is `Unit` for the closure tests and `Feature` for the database-backed default similarity (Unit tests have no database). `ranked()` helper is in `tests/Pest.php`.
- Not done, as instructed: the `cover-tile` reason label and "Why this?" popover of 6.7 (UI).

### Accepted deviations (6.8 non-UI)
- `RecommendationLogger::log` takes `iterable<ServedItem>` and returns the new ids keyed `{shelf}:{media id}` (the plan's `Collection<Shelf>` and `void`): the cache needs the recommendation ids, and a `Shelf` holds no scores or features. It writes nothing for an opted-out reader, or when there is no active `hybrid-weights` version (`model_version_id` is required); the shelves still build then.
- Only the candidate shelves are cached (`home:shelves:{user_id}:{mature|gated}`, `cache_minutes`), as `[media id, recommendation id, label]` lists; Continue Reading, the editorial collections and Explore by Subject are read live through the existing classes, as Home reads them today. Cached ids are loaded fresh through `unmerged()->visibleTo($user)`, so a deleted, merged or newly gated title drops out of a cached shelf. `ForgetHomeShelves` forgets both access variants.
- Each tile model carries two attributes: `recommendation_id` (null when nothing was logged) and `reason_label`; the UI reads them. The editorial collections keep their own keys (`collection-{id}`) in the "Your Collections" slot, so Home can replace its present list one for one (hero and `x-shelf` bands are the UI part). `trending` and `new-releases` now come from `TrendingSource` and `NewReleasesSource` (library and dismissed excluded, preferred types and languages applied), not from `HomeShelves::picks`; `HomeShelves` stays the guest path.
- `because-you-read` uses `SeedItems::mostRecent` and is left out when that title is gated for the reader (F8). `similar-to` is the latest favorite other than that title, via `ContentSimilarSource::similarTo` (lsa neighbors of that one title). Labels: fixed for trending, new release and exploration; the ranker's for `recommended` and for `popular-in-genres` (which shows no label when the ranker did not give a genre label). `PERSONALIZED` sources are `content_similar`, `collaborative`, `dewey_similar`, `popular_in_genres`, `exploration`; an opted-out reader gets trending, new releases and editorial only (plus Continue Reading, collections and subjects).
- The 25-query Home test and the story page `?rec` test of the plan are UI and wait for the design gate.

### Accepted deviations (F12, F13, 6.9)
- 6.9 polling: the plan has the job release itself every 30 s, but a released job comes back with the state it was queued with, so it could not remember its run. A step is instead one job that starts the service job and records the `ml_job_runs` row, then queues a fresh `RunMlJob` (carrying the row id and the remaining steps) delayed 30 s, which copies `status/metrics/error/finished_at` and does the same until `succeeded`, `failed` or two hours after the row's `started_at` (then failed with "did not finish within two hours"). An unreachable service while polling is retried until that deadline.
- A service that will not start the job releases it with backoff 30, 60, 300, 900 s (5 tries); no row exists until it starts, so retries open no duplicates, and `failed()` then records one failed row with the reason so the page shows it.
- `RunMlJob` takes `(name, params, then, mlJobRunId)` with `then` the list of remaining `[name, params]` steps, not the plan's `?int $then`.
- Scheduling uses `Schedule::job(...)->name('ml:...')` with a `when` on the token, so a deployment without the ML service does not log a failed run every night.
- The admin page lists the 30 newest model versions and 20 newest runs; failures show as a red status badge with the error in `text-meta text-ink-subtle`, like the providers page. Queue backlog is `Queue::size('default')`. Run now has one button per pipeline (item-cf, lsa, popularity) and re-checks `access-admin`.

### Accepted deviations (final review fixes)
- B1: a failed `version_id` check writes a new failed row named for the step that would have run, and leaves the train row `succeeded` (the service did succeed). The scheduled pipelines are `Schedule::call(fn () => RunMlJob::dispatchPipeline(...))` instead of `Schedule::job(...)`, so the running flag is taken at dispatch. Because the flag lives in the cache, a lost cache lets a second run start; the Python side's version pinning keeps that harmless.
- S4: `ShelfBuilder::build` reads the seeds of the two shelves first (`similarTo` of the latest read and of the latest favorite) and ranks those neighbors the pool did not hold in one extra `rank()` call; the cold-cache query count stays at 69.
- S5: `Media::scopeTrending(?int $limit = null)` with a limit adds, just before the query runs (`beforeQuery`, so it sees filters chained after the scope), `media.id in (first $limit ids of the filtered query by the index order union media_popularity.trending_percentile > 0)` and then orders by the blend. Exact because the blend adds at most `trending_weight` and only to media with activity. All callers pass the number of rows they take (`HomeShelves`, `TrendingSource`, `LandingShowcase`, `OnboardingPicks`, `showcaseCovers`). Without a limit (the `TrendingScopeTest` cases) the old full ordering is used, so results are unchanged but it is a full sort. `count()` and `paginate()` fail on this scope with or without a limit, as before (the order by stays in the aggregate).
- N1: the cache digest keeps `reason_media_id` per shelf and per tile. On read, a shelf whose heading names a title the reader may not see is left out (as a fresh build does with a gated seed), and a tile label naming one is dropped. One extra query when any reason id is cached; the warm read is 15 queries (was 14).
- N5: the exploration slot is `round(1 / epsilon)`; an epsilon of 0 gives none.
- N6: the seeded rows persist across the test suite (RefreshDatabase migrates once), so `ModelsPageTest` filters its version names.
- N8: labels use `:title` / `:genre` placeholders. The Unit `ExplanationTest` moved to `tests/Feature/Discovery/Recommendations/ExplanationLabelTest.php` because `__()` needs the application.
